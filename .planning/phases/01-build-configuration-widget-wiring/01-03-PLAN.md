<objective>
Complete BUILD-02's real-device acceptance criterion by registering the App Groups (+ iCloud)
capability for all three App IDs in the Apple Developer Portal and regenerating the cached Fastlane
Match provisioning profiles — the one piece of this phase's work that has no CLI/API path Claude can
execute, because it requires credentials only the human maintainer holds (per 01-RESEARCH.md's
Environment Availability table: "Apple Developer Portal access... agent has no credentials... no
code-only fallback exists").

Purpose: 01-01-PLAN.md wires `CODE_SIGN_ENTITLEMENTS` into the widget target's build settings, but
`CODE_SIGN_STYLE = Manual` + Fastlane Match means Xcode never auto-registers new capabilities with
the Developer Portal — the cached Match profiles don't know about the new entitlement until someone
with write access force-regenerates them (01-RESEARCH.md Pitfall 3).

Output: all three App IDs carry the App Groups capability in the Developer Portal, and the cached
Match profiles are regenerated to embed it.
</objective>

  <instructions>
    1. Sign in to https://developer.apple.com/account -> Certificates, Identifiers &amp; Profiles ->
       Identifiers.
    2. For each of the three App IDs — stress.ai.com, stress.ai.com.watchkitapp,
       stress.ai.com.widget — open its capability list and enable "App Groups" if not already
       enabled; confirm the App Group group.stress.ai.com exists (create it if missing) and is
       checked for all three App IDs.
    3. For stress.ai.com and stress.ai.com.watchkitapp only (not the widget), also enable "iCloud"
       with CloudKit checked, matching the com.apple.developer.icloud-container-identifiers /
       com.apple.developer.icloud-services entries already present in their .entitlements files.
    4. From the repo root, run `bundle exec fastlane setup_match` — the project's existing
       write-access lane (fastlane/Fastfile's `setup_match`, which calls
       `match(type: "appstore", readonly: false, force: true, api_key: api_key)`) — to regenerate
       all three App Store profiles so they embed the newly-enabled capabilities. This uses the
       same APP_STORE_CONNECT_API_KEY_*/MATCH_GIT_URL credentials already configured for this
       project's existing CI (fastlane/Matchfile, fastlane/Fastfile's api_key method); no new
       secret is introduced.
    5. If real-device (not simulator) manual QA of the widget is planned per
       01-VALIDATION.md's Manual-Only Verifications, also regenerate a Development profile for
       local device installs — no existing lane wraps this; run
       `bundle exec fastlane match development --force` ad hoc.
  </instructions>
  <verification>
