# Phase 1 — UI Design Contract

> Visual and interaction contract for the home-screen widget's rendering states. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase has exactly one UI surface — `StressMonitorWidget` (Small/Medium/Large
> home-screen families + Lock Screen accessories). No app screens change. This contract resolves
> the two open items 01-RESEARCH.md flagged: (1) whether the existing `isPlaceholder` path satisfies
> D-02's "explicit no-data fallback" (it does **not**, as written — see Widget State Contract), and
> (2) whether the permanently-empty history/baseline area (WIRE-01's deferred scope) needs its own
> empty treatment (Large **does** need one; Medium already has one).

## Design System

| Property | Value |
|----------|-------|
| Tool | none — native SwiftUI/WidgetKit target, no shadcn/web tooling applies |
| Preset | not applicable |
| Component library | none — native SwiftUI views (`StressMonitorWidget/Views/*.swift`) |
| Icon library | SF Symbols (system) + custom emoji glyphs via `WidgetStressTier.emoji` |
| Font | San Francisco (system), `.font(.system(size:weight:design:))`; Large's headline uses the `.rounded` design variant |

The widget target does **not** import the app's `Theme/DesignTokens.swift` (separate compiled
target/module — no shared framework, per root `CLAUDE.md`'s "Module & Target Layout" note). Its own
color vocabulary lives in `StressMonitorWidget/WidgetStressCharacter.swift` (`WidgetPalette`,
`WidgetStressTier`) and is already correct — reuse it, do not introduce a second palette.

## Spacing Scale

Declared values (must be multiples of 4) — reused verbatim from `Theme/DesignTokens.Spacing`
(already 8-pt compliant, confirmed by reading `StressMonitor/StressMonitor/Theme/DesignTokens.swift`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used inside a widget's fixed frame) |

**Exceptions:** `StressMonitorWidget/Views/*.swift` cannot import `DesignTokens` (separate target)
and already uses its own established literal-padding vocabulary: `4, 6, 8, 9, 10, 12, 14`. These are
**not all 8-pt multiples** (6, 9, 10, 14 are not — several of these are pre-existing *font sizes*
reused as padding-adjacent literals, not deliberate spacing choices).

This exception is scoped **narrowly to pre-existing, untouched elements only** — sibling views,
icons, and text this phase does not modify keep their existing literal values verbatim (e.g. Small's
existing face/ring padding, Medium's existing sparkline margins). Do not retrofit those to the 8-pt
scale; that would be an out-of-scope refactor.

This phase's own **new/changed elements use 4-multiple spacing exclusively** — no exception applies
to them:

| New/changed element | Spacing decision |
|---|---|
| Stale-state label swap (Small/Medium/Large) | Text-content-only substitution inside the existing label slot — introduces **no new spacing value** (the slot's pre-existing frame/padding is untouched; only the `Text` string/color changes). Nothing to declare here. |
| Large's new "Gathering data…" placeholder | New element this phase adds — use compliant 4-multiples: **8px** icon-to-text gap (`sm` token), placeholder `height: 80` (already a 4-multiple), **8px** vertical padding around the placeholder content. If Medium's existing icon-to-text gap (which this placeholder is modeled on) turns out to be one of the non-compliant literals (6, 9, 10, 14) when the executor reads the source, use **8px** for Large instead of copying that exact value — visual near-identity with Medium is a nice-to-have, 4-pt compliance for phase-new elements is not. |

Do not introduce `DesignTokens` into the widget target and do not invent new spacing constants beyond
the `xs`/`sm` values already declared in the scale above.

## Typography

Widget-context roles only (the app's dashboard typography contract in `Theme/DesignTokens.Typography`
/ `Font+WellnessType.swift` is untouched by this phase). Exactly 4 sizes, 2 weights, matching sizes
already in use by sibling text in the same views:

| Role | Size | Weight | Line Height | Applies to |
|------|------|--------|-------------|------------|
| Body | 9px | regular (400) | 1.3 | Empty-state body copy (Small/Medium); "Gathering data…" placeholder (Medium, and new for Large) |
| Label | 10px | regular (400) | 1.3 | Empty-state body copy (Large); Large's stale-state timestamp subtitle |
| Heading | 12px | medium (500) | 1.2 | Small/Medium stale-state relative-time label (replaces tier label); empty-state heading (Small/Medium) |
| Display | 13px | medium (500) | 1.2 | Large empty-state heading ("No Data Yet") |

**Body (9px) vs. Label (10px) — 1px step:** not widened, and not a defect. These two roles are
never rendered in the same widget instance at the same time — Body 9px is Small/Medium's
empty-state-body and Medium's "Gathering data…" copy; Label 10px is Large's empty-state body and
Large's stale-state timestamp subtitle. Each family only ever shows one of the two, so the near-equal
size is never perceived as a side-by-side contrast failure. Both sizes are pre-existing, reused
verbatim from each view's already-coded sibling text (not introduced by this phase); widening either
would mean changing an untouched, out-of-scope element in a different family's view — out of bounds
per "Surgical Changes."

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | System `.fill.tertiary` container material via `.containerBackground(.fill.tertiary, for: .widget)` | Widget background on every family — adapts to light/dark automatically; no fixed hex |
| Secondary (30%) | `.secondary` (system secondary label) + tier accent at 20% opacity (`tier.accent.opacity(0.2)` ring track) | Supporting/caption text, ring track, stale-state label text, "gathering data" copy |
| Accent (10%) | `WidgetPalette` tier color: `ripple #4FC3F7` (resting) · `blossom #A5D6A7` (calm) · `lumi #7986CB` (balanced) · `ember #FFAB91` (tense) · `zephyr #B39DDB` (overwhelmed) | Character ring + glow, fresh-state tier label text, Medium/Large sparkline line + area gradient — **fresh state only** |
| Destructive | not applicable | No destructive actions exist in widget UI this phase |

**Accent reserved for:** character-face ring/glow, fresh-state tier label text, sparkline line +
area-gradient fill (Medium/Large). Never applied to stale-state or empty-state text — those
intentionally render in `.secondary`/`.primary` so a glance can tell "this is live" from "this is
aged or absent" without reading the number (dual-coding: color *and* text both change together,
consistent with root `CLAUDE.md`'s "dual coding for stress levels" rule applied here to data
freshness rather than stress level).

**Primary visual focal point per family (fresh state):**

| Family | Focal point |
|--------|-------------|
| Small | The character ring/glow (`WidgetStressCharacter`) is the sole and primary anchor — it occupies most of the fixed frame, everything else is secondary caption text. |
| Medium | The character ring/glow in the left column remains the primary anchor; the sparkline in the right column is a secondary, supporting element. |
| Large | The character ring/glow beneath the header is the primary anchor; the header's tier-label title is a secondary text anchor, and the history chart (when present) is tertiary. |

This ordering is unchanged by this phase — stated here only to satisfy the design-quality checklist,
not as new behavior.

## Widget State Contract

> Supplements the sections above with the concrete per-family state matrix. This is the load-bearing
> content for the executor — the sections above declare tokens, this section declares which token
> applies where.

### Three data states (provider-level), one unaffected system state

| State | Condition | Resolution this phase |
|-------|-----------|------------------------|
| **Fresh** | `latestStress != nil` and `now - latestStress.timestamp ≤ 24h` (existing threshold, unchanged) | No change — existing `stressContent(stress:)` rendering is correct in all three home-screen views |
| **Stale** (new, distinct from Fresh and Empty) | `latestStress != nil` and elapsed `> 24h` | New: render `stressContent(stress:)` at `.opacity(0.6)`; replace the tier-label slot with the relative-time label described in Copywriting Contract (see per-family detail below) |
| **Empty** (never measured) | `latestStress == nil` | Must route to the already-coded `emptyStateView` in each view file — **not** to `placeholderView`. Today's provider logic (`isPlaceholder: latestStress == nil \|\| isStale`) conflates Empty and Stale into one boolean that always lands on `placeholderView` (generic "StressMonitor" branding, no explicit copy) — this is the exact gap 01-RESEARCH.md Assumption A3 flagged. The provider must expose enough state to distinguish the three cases (e.g. a `.fresh`/`.stale`/`.empty` state, not a single `isPlaceholder` bool) so the view's existing three-way `if/else if/else` branch reaches `emptyStateView` for true-empty. |
| OS gallery placeholder | WidgetKit's own `placeholder(in:)` protocol method (redacted preview shown while adding the widget, or Widget Gallery browsing) | **Unaffected — do not change.** This is a different concept from the app's "no data yet" state; it must keep using the existing generic `placeholderView` regardless of the three states above. Do not conflate the two. |

### Per-family stale-state treatment

| Family | Tier-label slot today (Fresh) | Stale replacement |
|--------|-------------------------------|--------------------|
| Small | `Text(tier.label)` — 12px semibold, tier-accent color | Swap to `Text(timestamp, .relative(.named))` — 12px medium, `.secondary` color. Face+ring dim to 0.6 opacity. No "Stale" word (68pt frame is too narrow) — the color/content swap is itself the signal. |
| Medium | Left column `Text(tier.label)` — 10px semibold, tier-accent color | Same swap as Small, applied to the left column only (relative time, `.secondary`, 12px). Right column (sparkline vs. "Gathering data…") is driven purely by `history.count`, independent of staleness — no double-signal needed there. |
| Large | Header title `Text(tier.label)` (20px bold, tier-accent) + subtitle `Text(timestamp, .relative(.named))` (10px secondary) | Keep the title as `tier.label` (still informative — "you were Tense 2 days ago"). Dim the whole `stressContent` to 0.6 opacity. Prefix the existing subtitle with **"Stale · "** → e.g. "Stale · 2 days ago". Large has room for the explicit word; Small/Medium do not. |
| Lock Screen (Rectangular/Circular/Inline) | Shows `tier.emoji` + `tier.label` whenever `latestStress != nil`, with **no** staleness check today | **Explicitly deferred this phase.** Lock Screen accessories have severe space constraints (≈30pt tall rectangular) and Apple HIG favors minimal glanceable content there; continuing to show the last-known mood indefinitely (today's behavior) is an acceptable UX trade-off for v1. Do not add stale styling to Lock Screen views in this phase — flag for a later phase if product wants it. |

### History/baseline permanently-empty treatment (WIRE-01 scope)

Because history/baseline publishing is explicitly out of this phase's scope (per 01-RESEARCH.md's
Gap, `WidgetDataProvider.saveHistory`/`saveBaseline` are never called), `entry.history` will be
empty for the lifetime of this phase, for every user, always — this is not a transient "first launch"
condition, it is the steady state until a future phase wires it.

| Family | Current behavior when `history.count < 2` | Resolution |
|--------|----------------------------------------------|------------|
| Small | No history UI exists at all | No change — nothing to fix |
| Medium | Already shows an explicit **"Gathering data…"** placeholder (icon `waveform.path.ecg` at 20px + 9px secondary text) in place of the sparkline | No change — this is the correct, already-built pattern; reuse it verbatim in Large (below) |
| Large | **Bug-adjacent gap:** `stressContent` unconditionally renders a `Divider()` before *and* after the history section, but the `historyChartSection` content itself is only rendered `if entry.history.count >= 2`. With history always empty this phase, this collapses to two `Divider()`s stacked directly on each other with no content between them — a visible layout artifact, not a graceful empty state. | **Add** the same "Gathering data…" placeholder Medium already uses (identical icon size 20px, identical 9px secondary copy, identical wording) inside the `if entry.history.count >= 2 { ... } else { ... }` gap, framed at `height: 80` to match `historyChartSection`'s existing frame height so the overall widget height does not visibly shift once history publishing lands in a future phase. |
