<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App → Backend (HTTPS) | Every non-/health request crosses this boundary carrying a Firebase ID token in the Authorization header |
| Firebase SDK → Firebase Auth servers | Anonymous sign-in and token refresh cross this boundary; tokens are minted server-side |
| Keychain / UserDefaults | Session ID persistence (UserDefaults key "stressChatSessionId"); no tokens stored (Firebase SDK manages its own token cache internally) |
| ChatViewModel → Backend | Derived stress scores (StressContextPayload: level/category/confidence/per-factor scores) cross this boundary; raw HealthKit samples do NOT |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing / Tampering | Firebase ID token in transit | high | mitigate | HTTPS-only (ATS default). Backend verifies token signature via Firebase Admin verifyIdToken using Google's public certs — forged tokens fail verification. |
| T-01-02 | Information Disclosure | stress_context payload over network | medium | mitigate | StressContextPayload sends only derived scores (stress level/category/confidence, per-factor HRV/HR/sleep/activity/recovery scores), never raw HealthKit samples. Matches existing CLAUDE.md privacy contract. |
| T-01-03 | Denial of Service | /chat endpoint flooding | low | accept | Backend enforces credit-based rate limiting (1 credit per message, 50 credit starting balance per D-07 / INSUFFICIENT_CREDITS). No additional client-side mitigation needed. |
| T-01-04 | Elevation of Privilege | Anonymous → Google account upgrade | medium | mitigate | Plan 02 implements Firebase account linking (not replacement) via signIn(with: credential) — preserves anonymous user's data when upgrading. |
| T-01-05 | Tampering | GoogleService-Info.plist in app bundle | low | accept | GoogleService-Info.plist is designed to be shipped in the app bundle (Firebase API keys are safe to expose — security comes from Firebase Auth + backend token verification, not from hiding the plist). Per Firebase documentation. |
| T-01-SC | Tampering | SPM package install (firebase-ios-sdk) | high | mitigate | D-01 is a user-locked one-way-door dependency addition. Legitimacy verified: firebase-ios-sdk is Google's official SDK (67k+ GitHub stars, verified publisher). No blocking checkpoint needed — the legitimacy is established. |
</threat_model>
