<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App → Google OAuth | Google Sign-In flow crosses this boundary; the OAuth exchange returns an idToken + accessToken |
| Anonymous → Google account link | Firebase account linking merges the anonymous user's credit balance + chat history with the Google user (preserves data) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | Google Sign-In credential exchange | medium | mitigate | GIDSignIn uses Google's official OAuth flow (PKCE, system browser). Credential verified by Auth.auth().signIn — forged credentials fail. |
| T-02-02 | Repudiation | Anonymous-to-Google account merge | low | accept | Firebase preserves the anonymous user's uid → linked credential maps to the same uid. No data loss on upgrade. |
| T-02-03 | Information Disclosure | Leftover Supabase tokens in Keychain | medium | mitigate | FirebaseAuthService.clearStoredCredentials() is called by DataDeleterService; the old Supabase Keychain accounts (com.stressmonitor.app / supabaseAccessToken / supabaseRefreshToken) should be explicitly deleted in the same wipe step — extend clearStoredCredentials to also try? KeychainService.delete for those legacy accounts so a returning user doesn't carry dead tokens. |
</threat_model>
