# Phase 3 — UI Design Contract

> Visual and interaction contract for a **remediation phase on an existing SwiftUI app**.
> This contract constrains fixes to the current surfaces. It does NOT introduce a new
> visual language: the approved design (cream canvas, plain surface cards, Ripple-blue
> accent — settings redesign 2026-09-02, commit `2b84862`) is the baseline being made
> accessible, not replaced. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Authority note:** root `CLAUDE.md` cites `documentation/references/ui-ux-design-system.md`
as the design-system reference — that file does not exist anywhere in the repo (verified by
`find . -name "ui-ux-design-system.md"` → no hits). The de-facto design authority is the
source itself: `StressMonitor/StressMonitor/Theme/` (DesignTokens, Color+Wellness,
Color+Extensions, Font+WellnessType, Gradients) + `StressMonitor/StressMonitor/Utilities/`
accessibility helpers. This spec codifies those tokens as the contract.

## Spacing Scale

Declared values (multiples of 4) — `DesignTokens.Spacing` (`Theme/DesignTokens.swift`), used in 257 places:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4 | Icon gaps, inline padding |
| sm | 8 | Compact element spacing |
| md | 16 | Default element spacing, card padding |
| lg | 24 | Section padding |
| xl | 32 | Layout gaps |
| xxl | 48 | Major section breaks |
| xxxl | 64 | Page-level spacing |

Exceptions (pre-existing, grandfathered — do not widen):

- `DesignTokens.Layout.minTouchTarget = 44` — the A11Y-01 constant; hit areas, not visual spacing.
- Button heights 52pt (`PrimaryButton`/`SecondaryButton`) — satisfies 44pt by construction.
- Corner radii 12 (`DesignTokens.Layout.cornerRadius`), 20 (`Spacing.settingsCardRadius`/`widgetRadius`), 26 (`PrimaryButton`) — geometry, not spacing.
- `Spacing` struct extras (`cardPadding 20`, `settingsCardSpacing 14`, `listRowSpacing 12`) — legacy Settings metrics in live use. Rule for this phase: **no new parallel spacing constants**; fixes on manifest surfaces reuse `DesignTokens.Spacing` or an existing `Spacing` value verbatim.

Dynamic Type interplay rule: spacing tokens are fixed; at AX sizes, spacing between stacked
elements may be reduced one step (e.g. lg→md) **only** where required to prevent clipping —
prefer allowing the container to scroll instead.

## Typography

Remediation contract on the existing scale — no new sizes, no new weights. The phase's job is
making this scale **actually scale**.

| Role | Size | Weight | Dynamic Type anchor (`relativeTo:`) |
|------|------|--------|-------------------------------------|
| Caption / footnote | 13 | regular 400 | `.caption` |
| Body | 17 | regular 400 | `.body` |
| Body emphasized / headline | 17 | semibold 600 | `.headline` |
| Section header | 22 | semibold 600 | `.title2` |
| Card title | 28 | bold 700 | `.title` |
| Large title (screen titles) | 34 | bold 700 | `.largeTitle` |
| Hero metric numeral | 72 | bold 700, `.rounded` | gauge class — see below |

Contract rules:

1. **Fixed-size fonts don't scale.** `Typography.*` and `Font.WellnessType.*` are bare
   `Font.system(size:)` — these ignore Dynamic Type entirely. Retrofit: redeclare each token
   as `Font.system(size:weight:design:)` composed with `.relativeTo(_:)`-anchored scaling
   (e.g. `Font.system(.body)` + `.bold()` modifiers, or `Font.custom`-style relative anchors),
   preserving today's rendered sizes at the Large (default) setting. Final rendered size at
   default settings must be byte-identical to today — this is a scaling retrofit, not a retype.
2. Line height: SwiftUI text-style leading (system defaults). Body wraps with `.lineLimit(nil)`;
   **no `minimumScaleFactor` shrink on manifest surfaces** (D-10) — text wraps, stacks, or the
   container scrolls.
3. Weights in active use: regular 400 + semibold 600, with bold 700 reserved for display
   numerals and screen titles only. Do not introduce other weights.
4. Gauge class (fixed-size, exempt from scaling per D-09): the stress-ring hero numeral (72pt
   rounded) and chart geometry render fixed-size but MUST carry an accessibility value/series
   (see Interaction & Assistive Contracts). Everything else on manifest surfaces scales
   through AX5.

### Stress-category palette — indicator class, dual-coded

Stress hues (`Color.stressColor(for:)`) are **status indicators**, not text colors:

- The hue may fill ring segments, icons, and ≥18pt-bold display numerals → bar is **≥3:1**.
- Category label text (e.g. `StressDualCodingModifier`'s `Text(category.displayName)` at
  caption size) renders in `adaptivePrimaryText`/`adaptiveSecondaryText` — **never** in the
  stress hue (no saturated hue reaches 4.5:1 on cream).
- Dual coding (hue + SF Symbol + display name) is mandatory wherever a category shows —
  existing `stressDualCoding` pattern.
- Dark variants all pass as indicators (relaxed 9.27, moderate 13.27, high 9.11, severe 5.50).
  **Light indicator variants that fail 3:1 on cream** — relaxed `#34C759` (2.18), moderate
  `#FFD60A` (~1.4), high `#FF9500` (2.16) — retune light-side to the darker indicator set;
  pre-computed passing candidates: relaxed `#00A000` (3.42), mild keep `#007AFF` (3.95),
  moderate `#8A5A00` (5.82) or `#9A5B00` (5.33), high `#B25400` (4.96) or `#CC0000` (5.78),
  severe keep `#FF3B30` (3.49). (Note: `#FFA500` in the `highContrast` set fails at 1.94 —
  fix its comment and value when touching that set.)

## Interaction & Assistive Contracts

The prescriptive rules the executor implements and the checker/auditor verify. These carry the
five success criteria.

### A11Y-01 — Touch targets (SC-1)

- Every interactive control on the 14 manifest surfaces has a hit area ≥
  `DesignTokens.Layout.minTouchTarget` (44×44pt), applied via
  `.minimumTouchTarget(DesignTokens.Layout.minTouchTarget)` (frame minWidth/minHeight +
  `contentShape(Rectangle())`) or an intrinsic ≥44pt control (52pt buttons already comply).
- The hit area may exceed the visual glyph (icon-only toolbar/close/info buttons get an
  invisible 44pt target) — the known risk classes on manifest surfaces: icon-only buttons,
  mood-check-in controls (`MoodCheckInView`), quick-action tiles (`QuickActionGrid`), watch-face
  preference rows, chart legends, character grid cards.
- Verification: per-surface Accessibility Inspector hit-target scan recorded in phase UAT;
  widget/watch surfaces exempt (not touch UI, D-02).

### A11Y-02 — Contrast (SC-2)

- The **token-pair unit test** (D-06) computes WCAG ratios from the semantic token definitions
  and asserts ≥4.5:1 (text) / ≥3:1 (large-text/UI) for the matrix in the Color section —
  light and dark. It joins the default CI suite (canonical invocation per 02-05).
- Fixes are token retunes only (D-04) — no per-site color overrides, no new `Color(hex:)`
  literals on manifest surfaces (the 424 existing inline call sites are out of scope this
  phase except where a manifest surface's inline color fails the sweep — then it moves to a
  token, not a patched literal).
- `HighContrastModifier.swift` is deleted (D-05); `PatternOverlay`/`ColorBlindnessSimulator`
  are audited for the same fate during A11Y-05.

### A11Y-03 — Reduce Motion (SC-3)

- **One app-wide helper** (D-12), e.g. `.wellnessMotion()`, owns ALL reads of
  `\.accessibilityReduceMotion` / `UIAccessibility.isReduceMotionEnabled`. Under Reduce Motion:
  transitions cross-fade (`.opacity` — fades are allowed; hard `.identity` cuts are not the
    goal), `repeatForever` loops stop (shimmer → static redacted), scale/offset/parallax
  effects are removed, character idle holds a static pose, celebrations render a static badge
  + `HapticManager` haptic. Existing pieces to consolidate: `Animation+Wellness.swift`,
  `AnimationPresets.swift` (`staggeredAppear`, `shimmerLoading`), `AccessibilityModifiers`
  (`accessibleAnimation`, `pressEffect`), `ScaleButtonStyle`.
- **Trust gate (D-13):** grep enumerates the helper's call sites; target state is zero raw
  `reduceMotion`/`isReduceMotionEnabled` references outside the helper's definition.
  Baseline measured 2026-09-05: **65 references across 13 files** in the app target.
  Consolidation is target-wide (includes exempt-from-sweep Onboarding/Paywall/Chat files).
- **Breathing (D-11, motion-essential):** under Reduce Motion the session defaults to haptic
  pulses + the text countdown line (copy above); the animated guide is an in-session opt-in
  via the "Breathing animation" switch. Breathing views do not adopt the blanket helper.

### A11Y-04 — Dynamic Type (SC-4)

- **Rework `.accessibleDynamicType()`** (D-10): defaults become — no `dynamicTypeSize` cap
  (scales through AX5), no `minimumScaleFactor` shrink, `.lineLimit(nil)`. Layout adapts
  (stack, wrap, `ViewThatFits`, scroll) — long text wraps or scrolls, never truncates.
  The AX3-capped `.limitedDynamicType()` remains available only behind an explicit dated
  exception note. `accessibleWellnessType*` in `Font+WellnessType.swift` gets the same rework
  or is deleted in favor of one modifier.
- **Adoption gate:** every manifest surface's root view applies the reworked modifier —
  grep-verified 1:1 against the D-03 manifest (enumeration, not counts). Current adopters:
  `DashboardView`, `SettingsView`, `MiniWalkView`, `BreathingExerciseView` (4 of 14; two more
  adopters — `MeasurementHistoryView`, `IAPPremiumView`/`PaywallView` — are orphan/exempt).
- **Font retrofit:** Typography tokens gain Dynamic Type anchors (see Typography rule 1).
- **Fixed-size exempt classes (D-09):** charts (Swift Charts / SwiftUICharts) render
  fixed-size geometry but expose an **accessibility series** — the one-line trend summary
  (VoiceOver entry) + per-point labels + `.updatesFrequently` via the existing
  `.accessibilityChart` shape; the gamified character illustration is exempt from scaling but
  labeled (`accessibilityLabel` + state value, copy above). Gauge numerals (stress-ring hero
  number) are gauge class with `.accessibilityStressLevel` value.
- **Human walkthrough:** AX5 (largest accessibility size) per manifest surface, light + dark,
  screenshots recorded in phase UAT (D-10 layer 2).

### A11Y-05 — Orphan deletion (SC-5)

See the appendix. Deletion from disk (no `#if` hiding), verified by a clean build of all
targets; the sweep manifest above is unaffected (all 14 surfaces are reachable).
