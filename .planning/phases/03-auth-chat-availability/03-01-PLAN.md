<objective>
Honestly gate AI Chat off for v1 and prove the streaming lifecycle is correct so it is ready when Chat re-enables in v1.1. No credential — expired or otherwise — is extractable from the Release binary; the Chat entry point visibly reflects "coming soon" rather than opening a dead-looking sheet; mid-stream dismissal cancels the in-flight request and a network drop preserves partial text.

Purpose: The app ships with a non-functional Chat behind a working-looking entry point. `SupabaseSecrets.swift` (gitignored but auto-compiled into every build by the `PBXFileSystemSynchronizedRootGroup`) leaks an expired JWT literal into the Release binary — `strings` extracts it, failing AUTH-01 outright. The two entry points (`ActionView`, `SettingsView`) open a `ChatBottomSheetView` whose "unavailable" state reads as a broken developer setup ("Connect Supabase Auth"), not an honest user message. The cancellation and partial-preservation logic (AUTH-03) already exists and is substantially correct, but has zero test coverage pinning the contract — so it could regress before v1.1. This plan closes all three with a tracer that proves the Release-binary exclusion end-to-end, then expands to the entry-point gate and the lifecycle TDD tests.

Output: A `#if DEBUG`-wrapped `SupabaseSecrets.swift`, a single-source-of-truth `ChatAvailability` gate read by both entry points and the view model, user-facing unavailable copy, and two new test bundles (availability + lifecycle) that pin AUTH-01/02/03 so they cannot regress.
</objective>
