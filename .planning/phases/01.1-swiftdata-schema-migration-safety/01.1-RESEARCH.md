# Phase 01.1 Research — SwiftData Schema Migration Safety

> **Source:** Consolidated from `axiom:swiftdata-auditor` audit (12 findings) + independent on-disk store inspection + source-code root-cause analysis. No separate researcher spawned — the audit was the research.

## Technical Approach

### Fix Option A — Pre-release, accept data loss (0.5 day)

Use when D5 = "no real user data to preserve" (pre-App-Store, no TestFlight users with stress history).

**Approach:**
1. Replace `fatalError` (`StressMonitorApp.swift:82`) with non-fatal recovery: DEBUG keeps `fatalError` for dev visibility; RELEASE falls back to a fresh container (`ModelConfiguration(schema:, isStoredInMemoryOnly:, allowsSave:)`) + telemetry log.
2. In DEBUG only, set `ModelConfiguration(schema:, isStoredInMemoryOnly:, allowsSave:, eraseDatabaseOnSchemaChange: true)` — accepts data loss on schema mismatch, which is fine for dev/testing.
3. Add property-level defaults to `StressMeasurement` non-optional fields: `isSynced: Bool = false`, `deviceID: String = CloudKitDeviceID.current`, `categoryRawValue: String = StressCategory.mild.rawValue`, `restingHeartRate: Double = 0`.
4. Resolve CloudKit inconsistency: either bind `cloudKitContainer: .identifier("iCloud.stress.ai.com")` matching entitlements, or remove CloudKit entitlement.
5. Delete orphaned root source set.

**Risks:** Any TestFlight user with real stress history loses their data on first launch of the fixed build. Acceptable only if D5 confirms no such users exist.

### Fix Option B — Preserve existing data (2-3 days)

Use when D5 = "real TestFlight users with stress measurement history."

**Approach:**
1. Reconstruct frozen `@Model` snapshots per `VersionedSchema`:
   ```swift
   enum AppSchemaV1: VersionedSchema {
       static var models: [any PersistentModel.Type] {
           [StressMeasurementV1.self, CharacterUnlockV1.self]
       }
       @Model final class StressMeasurementV1 {
           // ONLY properties that existed in shipping V1
           var timestamp: Date
           var stressLevel: Double
           var hrv: Double
           // NO multi-factor fields, NO confidences, NO #Unique
       }
       @Model final class CharacterUnlockV1 {
           var characterId: String
           // NO #Unique constraint in V1 if added later
       }
   }
   ```
2. Add `MigrationStage.custom` with `willMigrate`/`didMigrate` for non-lightweight changes (unique constraint dedup, property default backfill).
3. Replace `fatalError` with non-fatal recovery (same as Option A step 1).
4. Add property-level defaults (same as Option A step 3).
5. Resolve CloudKit + orphan cleanup (same as Option A steps 4-5).

**Risks:** Requires knowing the exact historical schema shapes. If intermediate builds shipped different `@Model` shapes, each needs its own `VersionedSchema`. Complex, error-prone.

### Recommendation

Given `.claude/CLAUDE.md` states the app is "feature-complete but not submittable" (pre-App-Store), **Option A is the default**. If TestFlight users exist with real data, escalate to Option B.

## Pattern Analysis

### Existing SwiftData patterns in the codebase

| Pattern | Location | Notes |
|---------|----------|-------|
| `VersionedSchema` + `SchemaMigrationPlan` | `StressMonitorApp.swift:31-63` | Structural pattern correct, but reuses live types — needs frozen snapshots |
| `@Model final class` | `StressMeasurement.swift`, `CharacterUnlock.swift`, `Habit.swift` | Correctly `final class`, not `struct` |
| Optional fields for lightweight migration | `StressMeasurement.swift:14-20` | Multi-factor fields are optional — correct pattern; non-optional sync fields are NOT — bug |
| `#Unique<Animal>([\.id])` | `CharacterUnlock.swift:10` | Only unique constraint in the codebase; not captured in migration |
| Enum persistence via rawValue companion | `StressMeasurement.swift:11,51-54` | `categoryRawValue: String` + computed `category: StressCategory` — correct pattern; `Habit` violates it (stores `HabitType` directly) |
| `try? context.save()` error swallowing | 4 sites | Acceptable for seed data; not for user data |

## External Dependencies

- **Apple SwiftData** (system framework) — no version control; behavior is iOS-version-dependent (iOS 17.0-17.4 had silent store-wipe bug, per the code comment at line26-29)
- **CloudKit** — entitlement-gated; if bound, requires all `@Model` attributes to have defaults (currently NOT satisfied for `StressMeasurement`)
- **SQLite** (via CoreData/SwiftData) — unique constraint enforcement; `#Unique` generates a backing `UNIQUE INDEX`

## Risks and Unknowns

1. **D5 unresolved:** Is there real TestFlight user data? Determines Option A vs B (0.5 day vs 2-3 days).
2. **Historical schema shapes unknown:** If Option B, need to know every intermediate `@Model` shape that shipped. Git history of `StressMeasurement.swift` and `CharacterUnlock.swift` is the source of truth.
3. **CloudKit scope:** Is SwiftData-CloudKit sync intended for v1? Entitlement says yes; config says no; orphaned schema says a third thing. Product decision needed.
4. **`Habit` enum persistence:** `HabitType`/`HabitSource` are stored as enum types directly (not via rawValue companion). SwiftData supports `Codable` enums but this is a known fragility point. Currently works (18 rows on disk) but worth monitoring.
5. **Persistent history tracking tables (`ACHANGE`, `ATRANSACTION`) exist on disk:** Store was created with CloudKit-style persistent history tracking. If Option A wipes the store, these tables are recreated cleanly.
