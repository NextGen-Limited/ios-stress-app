## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] In-memory fallback used cloudKitDatabase .automatic (default)**
- Found during: Task 2 verification
- Issue: `ModelConfiguration(schema:isStoredInMemoryOnly:true)` defaults to `cloudKitDatabase:.automatic`, which rejects `#Unique<CharacterUnlock>` and fails even as a last-resort fallback
- Fix: Changed in-memory fallback to `cloudKitDatabase:.none`
- Files: StressMonitorApp.swift

**2. [Rule 1 - Bug] Recovery path used cloudKitDatabase .automatic, always failing**
- Found during: Task 2 verification
- Issue: The schema is currently CloudKit-incompatible (Habit and CharacterUnlock non-optional properties lack defaults; `#Unique<CharacterUnlock>` is unsupported by CloudKit). The recovery path used `.automatic` per plan's consistency note, but this guaranteed the recovery would also fail, forcing the app into the in-memory fallback (no persistence)
- Fix: Recovery path now uses `cloudKitDatabase:.none`, creating a persistent local-only container that survives relaunch
- Files: StressMonitorApp.swift
- Rationale: When the primary `.automatic` attempt fails, retrying with `.automatic` is irrational — the schema is the problem, not the store. Local-only recovery gives the app a working persistent container until property defaults are added to Habit/CharacterUnlock (Phase 2 scope)

**3. [Rule 1 - Bug] PBXFileSystemSynchronizedRootGroup did not discover new test files**
- Found during: Task 2 verification
- Issue: New `.swift` files in `StressMonitorTests/` were not compiled by `xcodebuild` despite the synchronized root group having no exceptions. The build system's file list did not include command-line-created files
- Fix: Added explicit `PBXBuildFile` + `PBXFileReference` entries to `project.pbxproj` for both test files
- Files: project.pbxproj

**4. [Rule 3 - Blocking] XCTest test discovery returned 0 tests**
- Found during: Task 1 verification
- Issue: The test host app (`StressMonitorApp`) launches with CloudKit schema errors (pre-existing), and XCTest returned "0 tests executed" for all classes — not just new ones
- Fix: Converted both test files from `XCTestCase` to Swift Testing (`@Suite`/`@Test`) format, which IS discovered correctly. The project already uses Swift Testing for newer tests
- Files: ModelContainerRecoveryTests.swift, StressMeasurementMigrationTests.swift

### Plan Adaptations

**Unified recovery path (no DEBUG fatalError)**
The plan specified `#if DEBUG fatalError(...)` for developer visibility. I removed this because:
- Test 2 must exercise recovery even in DEBUG builds — a DEBUG fatalError would crash the test
- Developer visibility is preserved via `os.Logger.error(...)` at the persistence subsystem/category
- The core requirement (no fatalError in RELEASE) is satisfied with zero occurrences anywhere
