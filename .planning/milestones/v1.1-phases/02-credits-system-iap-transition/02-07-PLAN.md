<objective>
Close verification gaps 3 and 4 (CR-02 + CR-03, one root cause: server-side premium entitlement integrity). Today (1) verifyAndDecodeTransaction extracts only transactionId/productId/expiresAt — no revocationDate anywhere — and /premium/verify rejects only null expiry, so an expired subscription's Apple-signed JWS activates premium and a refunded transaction re-activates it; (2) iOS completePurchase calls syncSubscriptionEntitlementToServer BEFORE the revocation/expiry guard, so revocations delivered via Transaction.updates are actively POSTed to the server; (3) deductCredit and the chat 402 gate check plan_type alone while demotion happens only in the monthly cron — a subscriber whose term ends mid-month keeps unlimited chat for up to ~31 days.

Purpose: Full refund-abuse chain with no attacker skill required (buy annual → refund → Apple revokes → updates-listener syncs the revoked JWS → premium until original expiry), plus free premium for every churning subscriber. Money-path integrity for shipping.
Output: Backend revocation/expiry rejection at the verify seam, effective-premium enforcement at both live gates, iOS guard-before-sync ordering, all TDD-pinned.
</objective>
