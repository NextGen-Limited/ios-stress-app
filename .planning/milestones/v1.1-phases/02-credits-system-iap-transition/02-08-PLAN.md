Design decisions pinned by this plan (executor implements, does not re-derive):
- Revocation policy splits per route: /credits/redeem keeps rejecting revoked JWS via rejectingRevoked (a refunded pack must never grant); /credits/premium/verify unwraps to the raw verifier and treats a revoked SUBSCRIPTION payload as a demotion signal. The unwrap does NOT skip verification — the real decode still enforces the Apple signature chain; only the revocation throw moves.
- The decode-level ensureNotRevoked throw inside verifyAndDecodeTransaction MUST be removed — /premium/verify reuses that function, and the throw would 400 the revoked payload before the route ever sees revocationDate. rejectingRevoked stays exported and applied at the /redeem call site, so /redeem loses nothing (including for injected test verifiers).
- Replay-window guard: demote only where premium_until IS NOT NULL AND premium_until <= the revoked transaction's expiresAt AND premium_until > revocationDate. Rationale: a current term extending past the revoked transaction's own expiry was granted by a later transaction (renewal or re-subscription) and must not be shortened by replaying an old revocation. This closes the hole in the reviewer's literal SQL (its WHERE still demotes a newer term).
- Demotion re-post safety comes from the convergent UPDATE (second post matches zero rows), NOT from an iap_redemptions insert: the same apple_transaction_id can legitimately hold an earlier activation row (activated while valid, revoked later, re-posted for demotion) — a PK insert there aborts with 23505 into a 500. Pinned by the same-jws activation-then-revocation test.
- plan_type handling consistent with 02-07's effective-premium rule: the demotion UPDATE flips plan_type to 'free' only when least(premium_until, revocationDate) <= now() (mirroring demoteExpiredPremium's terminal state), and keeps the dated premium_until rather than nulling it (inert under the gates, preserves the actual end date). Future-dated revocations leave plan_type 'premium' until the term lapses; the cron janitor still runs unchanged.
- iOS revoked-subscription branch: post via the existing best-effort syncSubscriptionEntitlementToServer seam, then finish unconditionally, never touch premiumState locally (refreshEntitlements remains the authoritative local corrector and runs after handle()). Expired transactions stay unposted.
- WR-10 pack decision: NO clawback of already-granted pack credits on refund — a clawback needs a new server surface and risks negative balances against partially-spent credits; the reviewer's fix shape only requires breaking the loop. Refunded packs finish silently on device; grants already made are permanent.
