<objective>
Transition the iOS purchase surface from subscription-only to consumable credit packs with the deferred-grant pattern: verify on-device, redeem server-side, finish only after the ack, and retry unfinished transactions through the existing Transaction.updates listener.

Purpose: This is the revenue path. Getting the grant/finish ordering wrong permanently loses money (consumables cannot be restored — research Pitfall 2), so the ordering is pinned by protocol-level tests rather than trusted to review.
Output: Pack catalog + .storekit entries, deferred-grant purchase flow, redemption client call, Release-build proof.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| StoreKit → app | Apple-signed purchase results; only .verified payloads may grant |
| app → backend /credits/redeem | JWS string crosses with Bearer auth; server re-verifies independently |
| app ← backend | Balance response is advisory display state; never a gating authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2-09 | Repudiation / loss of funds | finish() before server ack | high | mitigate | Deferred-grant ordering enforced in code and pinned by CreditPurchaseFlowTests (finish-after-ack, no-finish-on-failure); unfinished redelivery via Transaction.updates is the retry path |
| T-2-10 | Tampering | granting on unverified transaction | high | mitigate | checkVerified throws on the unverified case (existing); pack path reuses it before any redeem call |
| T-2-11 | Tampering | client-minted grants | high | mitigate | Client never writes balance — only applies server responses; server independently verifies the JWS (02-02 T-2-05/06) |
| T-2-12 | Denial of Service (user-level) | redeem failure blocks finish forever | medium | accept | Unfinished transactions retry on every launch; error surfaces to purchase UI; server idempotency makes retries safe |
</threat_model>
